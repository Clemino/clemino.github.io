Le chapitre précédent a posé les fondations : la socket, l'adressage, le boutisme. Ce chapitre passe à l'action et construit un **serveur TCP** complet. TCP est le protocole du **mode connecté** ; le serveur suit une **séquence d'appels précise** — `socket`, `bind`, `listen`, `accept` — qu'il faut connaître **par cœur**, car la compléter est l'un des exercices d'examen les plus fréquents.

## TCP : un protocole connecté et fiable

Le protocole **TCP** (*Transmission Control Protocol*) est le protocole de transport du type `SOCK_STREAM`. Ses propriétés :

- **mode connecté** : une **connexion** est **établie** entre les deux extrémités **avant** tout échange de données ;
- **livraison fiable** : un total de contrôle (*checksum*) est calculé pour chaque paquet ; TCP **détecte** les pertes et **retransmet**, garantissant que les données arrivent **intègres**, **dans l'ordre** et **sans doublon** ;
- **flot d'octets** : une fois la connexion établie, les deux extrémités échangent un **flux continu** d'octets, comme à travers un tube.

C'est le protocole du Web, du courrier électronique, du transfert de fichiers — partout où la **fiabilité** prime. Le chapitre 4 présentera UDP, son opposé non connecté.

## La séquence du serveur TCP

Un serveur TCP suit **toujours** le même enchaînement d'appels. Le voici dans son ensemble — chaque étape est détaillée ensuite :

```text
   socket()    -> creer la socket d'ECOUTE
   bind()      -> lui attacher une adresse locale (IP + port)
   listen()    -> la passer en mode ecoute, ouvrir la file d'attente
   ┌──────────────────────────────────────────────┐
   │ accept()  -> attendre et accepter un client   │  ← boucle
   │            -> renvoie une NOUVELLE socket     │
   │ recv() / send()  -> dialoguer avec ce client  │
   │ close()   -> fermer la socket de SERVICE      │
   └──────────────────────────────────────────────┘
   close()     -> (a l'arret) fermer la socket d'ecoute
```

La distinction **socket d'écoute** / **socket de service** est le cœur de ce chapitre — nous y revenons en détail avec `accept`.

## Étape 1 — Créer la socket : `socket()`

Le serveur crée d'abord sa socket d'écoute. En TCP, le type est **`SOCK_STREAM`** :

```c
int server_fd = socket(AF_INET, SOCK_STREAM, 0);
if (server_fd == -1) {
    perror("socket");
    exit(EXIT_FAILURE);
}
```

Cette socket — qu'on appelle la **socket d'écoute** — est pour l'instant **anonyme** : elle n'a pas d'adresse. C'est `bind` qui lui en donne une.

## Étape 2 — Attacher une adresse : `bind()`

```c
#include <sys/socket.h>

int bind(int s, const struct sockaddr *adr, socklen_t lg_adr);
```

**`bind`** **associe** une **adresse locale** (une IP et un port) à la socket. Sans cela, le système ne saurait pas sur quel port le serveur attend ses clients. Ses paramètres :

- **`s`** — le descripteur de la socket à attacher ;
- **`adr`** — un pointeur vers la `struct sockaddr_in` (transtypée en `struct sockaddr *`) décrivant l'adresse locale : famille, **port**, **adresse IP** ;
- **`lg_adr`** — la **taille** de cette structure, obtenue par `sizeof`.

`bind` renvoie **`0`** en cas de succès, **`-1`** en cas d'échec.

On remplit la `sockaddr_in` du serveur ainsi :

```c
struct sockaddr_in adresse;

memset(&adresse, 0, sizeof(adresse));        /* tout a zero (sin_zero compris) */
adresse.sin_family      = AF_INET;            /* domaine Internet              */
adresse.sin_port        = htons(8080);        /* port d'ecoute, en ordre RESEAU */
adresse.sin_addr.s_addr = htonl(INADDR_ANY);  /* toute interface locale         */

if (bind(server_fd, (struct sockaddr *) &adresse, sizeof(adresse)) == -1) {
    perror("bind");
    exit(EXIT_FAILURE);
}
```

Trois points méritent l'attention.

- Le **port** passe par **`htons`** (16 bits → ordre réseau) — la règle inviolable du chapitre 1.
- L'adresse IP est **`INADDR_ANY`** : le serveur accepte les connexions sur **n'importe quelle** interface réseau de sa machine, sans coder son IP en dur. C'est l'usage standard. Si l'on mettait `0` dans `sin_port`, le système choisirait lui-même un port libre — peu utile pour un serveur, dont le port doit être **connu** des clients.
- Le `memset` initial met **toute** la structure à zéro, ce qui couvre le champ `sin_zero[8]`.

> ⚠️ Le **cast `(struct sockaddr *)`** et la **taille** sont indissociables : on remplit une `sockaddr_in`, on transtype en `(struct sockaddr *)`, et on passe `sizeof(struct sockaddr_in)`. Une erreur classique est de passer `sizeof(struct sockaddr)` (la structure générique) au lieu de `sizeof(adresse)` : il faut bien la taille de la structure **réellement utilisée**, donc `sizeof(adresse)`.

## Étape 3 — Ouvrir le service : `listen()`

```c
#include <sys/socket.h>

int listen(int s, int backlog);
```

**`listen`** fait passer la socket en **mode écoute** : à partir de cet appel, la socket est prête à **recevoir des demandes de connexion** des clients. Ses paramètres :

- **`s`** — le descripteur de la socket d'écoute (déjà `bind`ée) ;
- **`backlog`** — la **longueur maximale de la file d'attente** des connexions **en cours d'établissement**.

`listen` renvoie **`0`** en cas de succès, **`-1`** en cas d'échec.

Le **`backlog`** mérite une explication. Quand plusieurs clients se connectent **en même temps**, le serveur ne peut pas tous les traiter instantanément : les demandes de connexion sont mises dans une **file d'attente**. `backlog` fixe la **taille** de cette file. Une valeur usuelle est **5** (la valeur historique par défaut) ; les clients arrivant alors que la file est pleine voient leur connexion refusée.

```c
if (listen(server_fd, 5) == -1) {
    perror("listen");
    exit(EXIT_FAILURE);
}
printf("serveur en attente de connexions sur le port 8080...\n");
```

> ⚠️ `listen` ne **bloque pas** et n'**accepte** aucune connexion : il **prépare** la socket et **dimensionne la file d'attente**, c'est tout. C'est `accept` (étape suivante) qui attend effectivement les clients. Le `backlog` n'est **pas** le nombre de clients que le serveur peut servir — un serveur peut en servir une infinité au fil du temps —, c'est seulement le nombre de connexions pouvant **patienter simultanément** avant d'être acceptées.

## Étape 4 — Accepter un client : `accept()`

C'est l'étape **centrale**, et la plus subtile.

```c
#include <sys/socket.h>

int accept(int s, struct sockaddr *from, socklen_t *fromlen);
```

**`accept`** **extrait** la première connexion en attente dans la file et l'**établit**. Ses paramètres :

- **`s`** — le descripteur de la socket d'**écoute** ;
- **`from`** — un pointeur vers une `struct sockaddr_in` que `accept` **remplit** avec l'adresse du **client** qui se connecte (son IP, son port) ;
- **`fromlen`** — un pointeur vers un entier contenant, **en entrée**, la taille du tampon `from`, et que `accept` met à jour, **en sortie**, avec la taille réellement écrite. C'est un **paramètre entrée/sortie** : on l'**initialise** avec `sizeof` **avant** l'appel.

`accept` est un appel **bloquant** : il **suspend** le serveur tant qu'**aucun** client ne se présente. Dès qu'une connexion arrive, il revient.

### Le point capital : `accept` renvoie une *nouvelle* socket

> ⚠️ **`accept` ne renvoie PAS la socket d'écoute** : il crée et renvoie une **nouvelle socket**, distincte, déjà **connectée** à ce client précis. C'est la **socket de service**. La socket d'**écoute**, elle, **reste ouverte** et continue d'attendre **d'autres** clients.

C'est la distinction la plus importante du chapitre. Après `accept`, le serveur possède **deux** sockets :

| Socket | Rôle |
|---|---|
| **socket d'écoute** (`s`, renvoyée par `socket`) | reçoit les **demandes de connexion** ; **ne sert jamais** à échanger des données ; reste ouverte |
| **socket de service** (renvoyée par `accept`) | **connectée** à un client précis ; c'est sur **elle** qu'on fait `recv`/`send` ; on la **ferme** quand ce client est fini |

Le serveur **dialogue** sur la socket de service, et **`accept`e de nouveau** sur la socket d'écoute pour le client suivant. C'est ce qui permet de servir des clients **les uns après les autres** dans une boucle (et, au chapitre 5, **plusieurs à la fois**).

```c
struct sockaddr_in adr_client;
socklen_t          lg = sizeof(adr_client);   /* INITIALISER avant l'appel ! */

int sk_service = accept(server_fd, (struct sockaddr *) &adr_client, &lg);
if (sk_service == -1) {
    perror("accept");
    exit(EXIT_FAILURE);
}
/* server_fd reste ouverte ; sk_service est connectee au client */
printf("client connecte depuis %s:%d\n",
       inet_ntoa(adr_client.sin_addr), ntohs(adr_client.sin_port));
```

> ⚠️ **Le troisième argument de `accept` doit être initialisé.** `fromlen` est un paramètre **entrée/sortie** : avant l'appel, on lui donne la **taille du tampon** (`socklen_t lg = sizeof(adr_client);`). Oublier cette initialisation, ou passer une variable non initialisée, provoque un comportement indéfini. C'est une erreur fréquente dans les exercices à compléter.

## Étape 5 — Dialoguer : `recv` / `send` (ou `read` / `write`)

Une fois la socket de service obtenue, le serveur **échange des données** avec le client. Comme une socket connectée se comporte comme un descripteur de fichier, **deux jeux de primitives** sont possibles.

On peut utiliser les appels système **universels** `read` et `write`, **strictement identiques** à leur usage sur un fichier ou un tube :

```c
read(sk_service, buffer, taille);    /* recevoir : comme sur un fichier  */
write(sk_service, message, longueur); /* emettre : comme sur un fichier  */
```

Ou les primitives **spécifiques aux sockets**, `recv` et `send`, qui ajoutent un paramètre `flags` :

```c
#include <sys/socket.h>

ssize_t recv(int s, void *buf, size_t lg, int flags);
ssize_t send(int s, const void *buf, size_t lg, int flags);
```

- **`recv`** **reçoit** des données : elle remplit `buf` (de capacité `lg` octets) et **renvoie le nombre d'octets reçus** ; `0` si le correspondant a **fermé** la connexion ; `-1` en cas d'erreur.
- **`send`** **émet** les `lg` octets de `buf` et renvoie le **nombre d'octets envoyés**.

Le paramètre **`flags`** vaut **`0`** dans l'usage courant — `recv(s, buf, lg, 0)` est alors équivalent à `read(s, buf, lg)`. Il existe aussi `recvfrom`/`sendto` (réception/émission avec adresse explicite, indispensables en **UDP**, chapitre 4) et `recvmsg`/`sendmsg`.

```c
char buffer[1024] = {0};

/* recevoir le message du client */
ssize_t n = recv(sk_service, buffer, sizeof(buffer) - 1, 0);
if (n > 0) {
    buffer[n] = '\0';
    printf("message du client : %s\n", buffer);

    /* repondre au client */
    const char *reponse = "Message bien recu !";
    send(sk_service, reponse, strlen(reponse), 0);
}
```

## Étape 6 — Fermer : `close()`

```c
#include <unistd.h>

int close(int s);
```

`close` **libère** une socket : le descripteur, l'espace de stockage associé et, le cas échéant, la **connexion**. Le serveur ferme **deux** sockets, à deux moments distincts :

- la **socket de service** : **dès que le dialogue avec ce client est terminé** — à chaque tour de boucle ;
- la **socket d'écoute** : seulement à l'**arrêt** du serveur (souvent jamais, le serveur tournant indéfiniment).

> ⚠️ Ne pas fermer la socket de service à la fin de chaque client provoque une **fuite de descripteurs** : à chaque `accept`, un nouveau descripteur est créé ; sans `close`, ils s'accumulent jusqu'à épuiser la table des descripteurs du processus. Règle : **un `accept`, un `close`** de la socket de service.

## Serveur TCP complet

Voici un serveur TCP complet, conforme au cours : il accepte un client, lit son message, répond, puis se termine.

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>

#define PORT        8080
#define BUFFER_SIZE 1024

int main(void) {
    int server_fd, sk_service;
    struct sockaddr_in adresse, adr_client;
    char buffer[BUFFER_SIZE] = {0};

    /* 1. creer la socket d'ECOUTE (TCP) */
    if ((server_fd = socket(AF_INET, SOCK_STREAM, 0)) == -1) {
        perror("socket");
        exit(EXIT_FAILURE);
    }

    /* 2. preparer l'adresse locale et l'attacher (bind) */
    memset(&adresse, 0, sizeof(adresse));
    adresse.sin_family      = AF_INET;
    adresse.sin_addr.s_addr = htonl(INADDR_ANY);   /* toute interface locale */
    adresse.sin_port        = htons(PORT);         /* port d'ecoute          */

    if (bind(server_fd, (struct sockaddr *) &adresse, sizeof(adresse)) == -1) {
        perror("bind");
        exit(EXIT_FAILURE);
    }

    /* 3. passer en mode ecoute (file d'attente de 5) */
    if (listen(server_fd, 5) == -1) {
        perror("listen");
        exit(EXIT_FAILURE);
    }
    printf("en attente de connexion sur le port %d...\n", PORT);

    /* 4. accepter un client -> NOUVELLE socket de service */
    socklen_t lg = sizeof(adr_client);
    sk_service = accept(server_fd, (struct sockaddr *) &adr_client, &lg);
    if (sk_service == -1) {
        perror("accept");
        exit(EXIT_FAILURE);
    }
    printf("client connecte : %s:%d\n",
           inet_ntoa(adr_client.sin_addr), ntohs(adr_client.sin_port));

    /* 5. dialoguer : lire la requete sur la socket de SERVICE */
    ssize_t n = recv(sk_service, buffer, sizeof(buffer) - 1, 0);
    if (n > 0) {
        buffer[n] = '\0';
        printf("message du client : %s\n", buffer);

        /* repondre au client */
        const char *reponse = "Message bien recu !";
        send(sk_service, reponse, strlen(reponse), 0);
        printf("reponse envoyee\n");
    }

    /* 6. fermer la socket de service, puis la socket d'ecoute */
    close(sk_service);
    close(server_fd);
    return 0;
}
```

Ce serveur ne traite **qu'un seul** client puis s'arrête. Pour en servir **plusieurs à la suite**, il suffit d'**entourer** les étapes 4 et 5 d'une **boucle** `while (1)`, le `close(sk_service)` étant fait à chaque tour :

```c
while (1) {
    socklen_t lg = sizeof(adr_client);
    int sk = accept(server_fd, (struct sockaddr *) &adr_client, &lg);
    if (sk == -1) { perror("accept"); continue; }

    /* ... dialoguer avec ce client sur sk ... */

    close(sk);            /* client suivant au prochain tour */
}
```

Ce serveur reste cependant **séquentiel** : tant qu'il dialogue avec un client, les autres **attendent**. Le chapitre 5 lèvera cette limite avec le **serveur concurrent**.

## Le piège « Address already in use » : `SO_REUSEADDR`

À l'arrêt d'un serveur TCP, le port qu'il occupait n'est **pas libéré immédiatement** par le système : la socket **connectée** de la connexion qui vient de se fermer reste un certain temps dans l'état **`TIME_WAIT`**, le temps de s'assurer qu'aucun paquet retardataire de cette ancienne connexion ne traîne encore sur le réseau. C'est cette socket connectée attardée qui maintient le port occupé.

Conséquence : si l'on **relance** le serveur **aussitôt**, le `bind` **échoue** avec l'erreur **`EADDRINUSE`** (« *Address already in use* ») — un grand classique, source de confusion. La solution est l'option de socket **`SO_REUSEADDR`**, posée avec **`setsockopt`** :

```c
#include <sys/socket.h>

int setsockopt(int s, int niveau, int option,
               const void *valeur, socklen_t lg);
```

`setsockopt` règle une **option** d'une socket. Pour autoriser la **réutilisation immédiate** de l'adresse :

```c
int oui = 1;
if (setsockopt(server_fd, SOL_SOCKET, SO_REUSEADDR,
               &oui, sizeof(oui)) == -1) {
    perror("setsockopt");
    exit(EXIT_FAILURE);
}
```

- **`SOL_SOCKET`** — le **niveau** de l'option (ici, le niveau « socket » général) ;
- **`SO_REUSEADDR`** — l'**option** : « autoriser la réutilisation de l'adresse locale » ;
- la **valeur** est un `int` non nul (`1`), passée **par adresse**.

> ⚠️ **`setsockopt(..., SO_REUSEADDR, ...)` se place entre `socket` et `bind`** — jamais après. Sans cette option, redémarrer un serveur tout juste arrêté échoue souvent sur `bind` (`EADDRINUSE`), à cause du port encore en état `TIME_WAIT`. Avec `SO_REUSEADDR`, le `bind` réussit immédiatement. C'est l'ajout standard de tout serveur TCP destiné à être relancé souvent — typiquement, pendant le développement et les tests.

```c
/* sequence serveur complete et robuste */
int server_fd = socket(AF_INET, SOCK_STREAM, 0);
int oui = 1;
setsockopt(server_fd, SOL_SOCKET, SO_REUSEADDR, &oui, sizeof(oui));  /* ICI */
bind(server_fd, (struct sockaddr *) &adresse, sizeof(adresse));
listen(server_fd, 5);
```

> **À retenir**
> - **TCP** (`SOCK_STREAM`) est un protocole **connecté** et **fiable** : la connexion est établie avant l'échange, les données arrivent **intègres**, **dans l'ordre** et **sans perte**, sous forme de **flot d'octets**.
> - La séquence du serveur TCP est **`socket` → `bind` → `listen` → `accept` (en boucle) → `recv`/`send` → `close`** — à connaître par cœur.
> - **`bind(s, (struct sockaddr *) &adr, sizeof(adr))`** attache une **adresse locale** (IP + port) à la socket ; côté serveur, `sin_addr` = **`INADDR_ANY`**, `sin_port` = **`htons(port)`**.
> - **`listen(s, backlog)`** passe la socket en mode **écoute** et fixe la taille de la **file d'attente** des connexions (usuellement 5) ; il ne bloque pas et n'accepte rien.
> - **`accept(s, ...)`** **bloque** jusqu'à l'arrivée d'un client et renvoie une **NOUVELLE socket** — la **socket de service**, connectée à ce client. La **socket d'écoute reste ouverte** pour les clients suivants. Son 3ᵉ argument (`fromlen`) doit être **initialisé** avec `sizeof` avant l'appel.
> - On **dialogue** sur la **socket de service** avec `recv`/`send` (ou `read`/`write`), `flags` = `0` ; on la **ferme** (`close`) à la fin de **chaque** client ; la socket d'écoute n'est fermée qu'à l'arrêt du serveur.
> - L'option **`SO_REUSEADDR`** (via **`setsockopt`**, posée **entre `socket` et `bind`**) évite l'échec `EADDRINUSE` (« Address already in use ») au redémarrage rapide d'un serveur.
