## Idée centrale

Un modèle n'est jamais neutre. Derrière chaque choix technique se cache un choix de valeurs, qui peut **distribuer les bénéfices et les préjudices** entre les personnes concernées.

## L'exemple TalentScore

Le cours prend un outil de recrutement fictif, TalentScore, et pose une question d'audit à chaque choix.

| Choix | Exemple TalentScore | Question d'audit |
|---|---|---|
| **Objectif** | Recruter un bon candidat | Bon selon quels critères ? |
| **Proxy** | Score à un test de code | Quelle compétence reste invisible ? |
| **Seuil** | Entretien si score ≥ 0,70 | Quel coût pour les faux négatifs ? |
| **Données** | Historique des recrutements | Qui manque dans cet historique ? |

Un **proxy** est une grandeur mesurable utilisée à la place de ce qu'on veut vraiment évaluer. Le test de code mesure une compétence, pas toutes.

> **À retenir**
> Un choix technique peut distribuer les bénéfices et les préjudices. L'audit consiste à rendre ces choix visibles et discutables.

## Pièges classiques

- Penser que le seuil est un détail : il décide qui est écarté, et les **faux négatifs** sont des candidats valables refusés.
- Oublier que l'historique ne contient que les personnes recrutées par le passé.
